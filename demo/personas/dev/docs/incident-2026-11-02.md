# Incident: duplicate charges at checkout (2 Nov 2026)

**Status:** mitigated, fix in progress (orders-412)

## What happened

Between 09:31 and 10:13 UTC, Stripe calls timed out after 8 s. The client retried, and Stripe had
already charged the card, so some customers were charged twice. Acme Corp was charged twice for
the same £520 order.

## Why

`chargeCard` doesn't send an idempotency key, so a retry is a new payment as far as Stripe is
concerned.

## Also found

The request logger writes the whole body on errors, including card numbers and emails
(orders-415). Staging logs from that morning are in `logs/checkout-errors.log`; delete them once
the fix ships.

## Actions

- [ ] Send an idempotency key derived from the order id (orders-412)
- [ ] Stop logging request bodies; log the account id only (orders-415)
- [ ] Refund the duplicate charges (billing team)
